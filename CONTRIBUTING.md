# Contributing

The guiding rule is numerical equivalence with the R package: any change to the core must keep `pytest` green against the R fixtures, and new features that exist in R should come with new fixtures generated by `tools/make_fixtures.R` (add the R calls there, re-run, commit the outputs).

Setup:

    pip install -e ".[dev]"
    pytest
    ruff check src tests

Regenerating fixtures needs R with the packages dlnm, splines and jsonlite:

    Rscript tools/make_fixtures.R

Style: keep the Python close to the R source structure (one function per R routine, same names) so that the two can be read side by side. British spelling in prose. Docstrings say what the R equivalent is.

Ports to other languages are welcome as separate repositories or as subdirectories (`rust/`, `julia/`) validated against the same `tests/fixtures/`.
